# Cronograma da Disciplina – Período 2025.2

## Planejamento da Disciplina

A disciplina foi estruturada com foco no desenvolvimento de projetos reais para empresas juniores da região. Inicialmente, os encontros presenciais foram destinados à apresentação da proposta, formação das equipes, definição dos papéis dos participantes e organização dos canais de comunicação entre estudantes e clientes.

Após essa etapa introdutória, os alunos iniciaram o levantamento de requisitos diretamente com as empresas atendidas, estabelecendo uma comunicação contínua que permaneceu ativa durante todo o semestre. Além do contato entre as equipes e os clientes, houve acompanhamento constante dos ministrantes da disciplina, responsáveis por orientar o andamento dos projetos e auxiliar na comunicação entre as partes. Os ministrantes também participaram das reuniões iniciais com as empresas, realizando a apresentação formal das equipes e facilitando o estabelecimento da relação entre estudantes e clientes, sem necessariamente intervir nas decisões e definições dos projetos.

A partir da etapa de levantamento de requisitos, a disciplina foi conduzida por meio de entregas periódicas, contemplando a definição das tecnologias utilizadas, a elaboração do design das soluções e o desenvolvimento dos sistemas propostos.

O processo priorizou a aplicação prática dos conhecimentos, a interação com clientes reais e o trabalho colaborativo em equipe. Ao final do período, os grupos apresentaram o estado atual dos projetos desenvolvidos, compartilhando os resultados alcançados e as experiências adquiridas durante a execução das atividades.

## Tecnologias Utilizadas nos Projetos

As equipes tiveram autonomia na escolha das tecnologias, a partir dos fundamentos trabalhados no semestre anterior. As soluções desenvolvidas utilizaram tecnologias web modernas para front-end e back-end, com versionamento via Git e GitHub.

Cada equipe montou um conjunto de ferramentas diferente de acordo com os requisitos do projeto e a experiência do grupo. A seguir descrevemos, por categoria, as tecnologias que foram adotadas e como foram utilizadas em 2025.2.

- **Linguagens e runtimes:**
	- Equipe A: PHP (servidor), JavaScript (comportamento cliente), HTML5 e CSS3 (marcaçao e estilos).
	- Equipe B: JavaScript — React no front-end e Node.js no back-end.
	- Equipe C: JavaScript (React) no front-end e Ruby (Ruby on Rails) no back-end.

- **Frameworks e bibliotecas:**
	- Equipe A: Laravel (framework PHP) — usado para roteamento, controllers e camada de persistência (ORM Eloquent).
	- Equipe B: React (biblioteca de UI), Tailwind CSS (estilização utilitária) e Express.js (framework minimal para Node.js) — usados para construir uma SPA, estilização via utilitários e APIs REST.
	- Equipe C: React (front-end) combinado com Ruby on Rails (back-end) e Tailwind CSS — Rails utilizado para APIs e ActiveRecord para acesso ao banco; Tailwind adotado para implementação de estilos e componentes responsivos.

- **Banco de dados e persistência:**
	- Todas as equipes utilizaram PostgreSQL como banco relacional principal, com migrações e scripts de seed para gerenciar o esquema e dados de desenvolvimento.
	- ORMs/abstrações: Eloquent (Laravel), ActiveRecord (Rails) e bibliotecas de acesso para Node/Express (ex.: Sequelize/knex) conforme necessidade do projeto.

- **Front-end e UI:**
	- Marcação e estilos: HTML5, CSS3 (possível uso de pré-processadores e bibliotecas de componentes conforme a equipe). Tailwind CSS foi adotado pelas equipes B e C como solução de estilização utilitária para acelerar a construção de layouts, garantir consistência e facilitar manutenção.
	- Componentização: React para as equipes B e C, permitindo desenvolvimento de componentes reutilizáveis e roteamento cliente.
	- Prototipação e design: Figma foi utilizado por todas as equipes para criar mockups, protótipos interativos e guias de estilo.

- **Versionamento, colaboração e revisão de código:**
	- Git e GitHub foram usados por todas as equipes para versionamento, pull requests, code review e integração com outras ferramentas (issues, actions).

- **Gerenciamento de projeto e rastreamento de tarefas:**
	- Equipe C utilizou Jira para gestão ágil (backlog, sprints e acompanhamento de tarefas). As demais equipes não utilizaram ferramentas de gestão ágil específicas.

- **Outras ferramentas de apoio:**
	- Ferramentas de comunicação (Meet/Discord/), navegadores para testes e utilitários de depuração e inspeção.

## Uso de IA Generativa

As equipes empregaram técnicas de IA generativa como apoio ao desenvolvimento e à produção de artefatos. Os usos mais comuns incluíram:

- Geração de textos auxiliares (descrições, conteúdo estático e microcopy para telas);
- Sugestões e snippets de código para acelerar implementações e resolver dúvidas pontuais;
- Criação de dados de teste e mocks para populações iniciais do banco durante a fase de desenvolvimento;
- Apoio à ideação de soluções de UX e variações de copy durante as etapas de prototipação;

As equipes adotaram princípios de uso responsável: revisão humana obrigatória das saídas geradas e cuidado com dados sensíveis de clientes.

## Levantamento de Requisitos dos Projetos (detalhe)

Não foi adotado um modelo padronizado de documento de requisitos. Cada equipe, liderada pelo seu Líder, foi responsável por estruturar o documento conforme seu entendimento, tendo como referência os objetivos identificados nas reuniões com o cliente: o que o cliente queria, como, quando, com qual finalidade e exemplos de referência. Os documentos produzidos foram revisados e corrigidos pela coordenação, o que revelou bom desempenho das equipes nessa etapa.

Essa escolha foi intencional: buscou-se avaliar a capacidade dos estudantes de organizar informações sem um template prescrito, simulando a autonomia exigida no mercado.

## Reuniões com Clientes dos Projetos

As reuniões foram conduzidas pelo Líder de cada equipe, sem roteiro padronizado. O foco era compreender: o que o cliente desejava, como imaginava a solução, quando precisava, qual a finalidade do sistema e quais referências visuais ou funcionais poderiam orientar o desenvolvimento.

Reuniões ocorreram nas seguintes etapas:
- Levantamento inicial de requisitos
- Validação do design e protótipos
- Demonstração de versões parciais do sistema
